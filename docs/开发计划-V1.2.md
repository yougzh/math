## 0. 实施总原则（六条，冲突时优先级从高到低）

1. **最小闭环优先**
   第一条要跑通的链是：
   `Competency → Pattern → Item → Attempt → Proficiency → Planner`
   任何功能，如果不能接进这条链，就不属于 P0 ～ P3。

2. **垂直切片优先**
   不做"每个宇宙各做一个壳"。只把 **🚂 数字车站** 的一条能力链做完整、做透，再复制。

3. **内容与代码分离**
   题目、提示链、故事、错误规则全部走 `content/**/*.yaml`，经 Content Compiler 编译入库。代码里不允许出现题目字面量。

4. **后端是学习状态的唯一权威**
   前端只提交事件、渲染反馈。前端可以做即时判定用于体验，但服务端判定为准并记录不一致。

5. **一切阈值、权重、规则可配置、可回放**
   熟练度算法是纯函数 + 版本化配置。改算法后必须能用历史数据重跑（Learning Replay）。

6. **MVP 边界清单不动摇**
   ❌ 排行榜 ❌ 社交 ❌ 多语言 ❌ 完整小学数学 ❌ Phaser/PixiJS ❌ 复杂 BKT ❌ LLM 出题 ❌ LLM 自由讲题

## 1. 阶段总览

| 阶段 | 目标 | 核心产出 | 完成判据（Gate） | 前置 |
|---|---|---|---|---|
| **P0** | 学习模型地基 | 数据模型 + 熟练度状态机（纯函数）+ Replay 原型 | 给定固定 attempt 序列，状态机输出可重复；改阈值后 replay 可重跑且结果自洽 | — |
| **P1** | 内容生产体系 | YAML/JSON Schema + Compiler CLI + 首批内容 | `validate/lint` 全绿；10 Competency / 7+ Pattern / 10 Template / 20～30 Item 入库 | P0-02/03 |
| **P2** | 数字车站垂直切片 | 端到端跑通一条链 + 3 个故事（后补到 10） | 一个孩子能完成：故事 → 答题 → 提示 → 提交 → 状态更新 → 次日计划改变 | P0、P1 |
| **P3** | 自适应引擎 | Planner / Scheduler / Diagnosis / 升级回退 / 模拟测试 | 7 类模拟孩子 × 30 天无异常；无过早升级、无难度断层、无复习过载 | P2 |
| **P4** | AI 教练 | 规则提示 → LLM 表达 → 4 个 Validator + Fallback | 泄题率 0；LLM 失败时 100% 回退规则文本；提示后继续尝试率可观测 | P2、P3 |
| **P5** | 成长体系 | 成长树 / 材料 / 建造 / 解锁 / 成就 | 材料奖励来自真实数学表现；解锁进度由 competency 驱动 | P3 |
| **P6** | 家长端 | 能力画像 + 熟练度 + 薄弱点 + 建议 | 报告能回答"不是不会，是流畅度不足"这类结论 | P3 |
| **P7** | 扩展宇宙 | 侦探社 / 商店 / 建造王国 | 数字车站验证成功后复制（复用 P1 内容体系与 P3 引擎，不新增引擎代码） | P6 |

**关键路径：** `P0 → P1（最小可运行） → P2 → P3 →（P4 ∥ P6）→ P5 → P7`

P2 与 P1 后半段可并行：前端交互组件不依赖全部内容，只依赖 Item Schema 冻结。

## 2. 开工前必须拍板的工程决策（含推荐方案）

这 6 条会渗透到所有代码，越晚改代价越大。

| # | 决策点 | 推荐方案 | 理由 |
|---|---|---|---|
| D1 | `story_beat` 绑定固定 item 还是"题目槽位" | **绑 `story_challenge_slot`（一等实体，不是 JSON 字段）**；Slot 声明 `pattern / competency / difficulty 区间 / selection_policy / review_policy / estimated_time`，运行时由 Planner 选具体 item | 绑死 item 会让自适应完全失效——同一故事对强孩子太简单、对弱孩子太难。Slot 独立成表后，"这里必须是 make_ten，但孩子最近连续做过 make_ten 就换 decompose" 这类策略不需要改故事 |
| D2 | 等级（🌱🌿🌳⭐🔥）存库还是算出来 | **派生值，不落库为权威**。只存 5 个原始信号 + 样本数 + `algorithm_version` | 改算法后必须能整表重算；存死等级 = 无法调参 |
| D3 | `attempt` 与 `learning_event` 关系 | 一次提交 = 1 条 attempt（快照）+ 1 条 event（append-only），**同一事务** | attempt 便于查询，event 便于回放与算法演进 |
| D4 | 前端能否判对错 | **双轨**：前端即时判定给体验，服务端判定为准，不一致写 `judgement_mismatch` | 儿童体验不能等网络；但数据可信度必须由后端保证 |
| D5 | 冷启动怎么初始化 | **Unknown → Probe**，前 3～5 次 `assessment=true`，权重 0.5 且**不参与升级判定** | 避免用随机初始值污染前两周的状态 |
| D6 | 时间语义如何冻结 | 采集 `response / active / thinking / idle_segments`，阈值 `<5s 正常思考 / 5–30s 疑似停顿 / >30s 疑似离开` | 思考本身是学习；把停顿一律剔除会误伤 |
| D7 | Planner 直接选"题目"还是先决定"学习意图" | **先定 Learning Intent**（强化 fluency / 复习 / 测迁移），再经 Slot → Item Selection 落到具体题目 | 直接选题会让规划器被题目细节绑死：策略无法复用、无法解释、无法回放 |

> D1 / D2 / D6 已升级为**不可随意修改的决策**，见 `docs/adr/`。
> 冲突时以 ADR 为准；要改动必须先写新的 ADR 覆盖旧的。

### 2.1 学习决策链（系统的大脑）

```
Child State
     ↓
Learning Intent        # 今天要达成什么（不是"做哪道题"）
     ↓
Daily Plan             # 时间预算切分：热身 / 核心 / 故事 / 思维 / 发现
     ↓
Story                  # 为什么做
     ↓
Challenge Slot         # 练什么（pattern + 难度区间 + 策略）
     ↓
Item Selection         # 具体做哪一道（filter → rank → select）
     ↓
Child Interaction
     ↓
Attempt                # 学习系统唯一事实入口
     ↓
Diagnosis
     ↓
Proficiency Update
     ↓
Next Learning Intent
```

**职责划分（三层，不允许越界）：**

| 层 | 回答的问题 | 不允许做的事 |
|---|---|---|
| Story | 为什么做 | 不允许指定具体题目 |
| Challenge Slot | 练什么 | 不允许指定具体题目 |
| Planner / Item Selector | 具体做哪一道 | 不允许改变故事与 slot 语义 |

反例（禁止）：`❌ 今天做 item_102`
正例：`✅ 今天：1) 强化 make_ten fluency  2) 复习 place_value  3) 测试 td_add_nocarry 的 transfer`

### 验收（可执行）

- `pytest tests/test_state_machine.py` 全绿，覆盖：正常升级、参数不达标不升级、回退触发、probe 期间不升级

- 修改 `config/algorithm/v0.yaml` 中任一阈值 → replay 可重跑，不抛异常，结果变化方向符合预期
- 100% 正确但速度慢 + 提示多 → level 最高只能到 🌳 会做（不允许 🔥）

### 风险

- 过度设计状态机 → 限制：MVP 只做 4 个信号 + 1 个派生等级，不做置信区间、不做遗忘曲线拟合
- 阈值拍脑袋 → 全部进配置，P3 用模拟数据回归调参

## 4. P1：内容生产体系

**目标：** 内容成为可校验、可生成、可预览、可导入的资产，而不是散落的题目。

### P1 拆分任务

| 编号 | 任务 | 说明 |
|---|---|---|
| P1-01 | YAML Schema 定义 | competency / pattern / template / item / story / misconception 六类 |
| P1-02 | JSON Schema 生成 | 由 YAML Schema 派生，接入 CI 强校验 |
| P1-03 | Compiler CLI 骨架 | `math-content validate / lint / preview / import / stats` |
| P1-04 | 结构校验 | 能力图无环、无孤立节点、prerequisite 存在；pattern 关联有效 competency |
| P1-05 | 题目校验 | 答案正确性（独立求解器复核）、steps 一致、hint 不泄答案、error_rule 存在、难度合理 |
| P1-06 | 认知有效性校验 | make_ten 必须个位和 ≥10；carry 必须个位和 ≥10；decompose 必须"值得拆"；place_value 必须真正区分十位/个位 |
| P1-07 | 故事校验 | item_slot 存在、时长合理、competency 覆盖、slot 难度落在故事允许区间 |
| P1-08 | preview | 本地起最小渲染页，肉眼过一遍交互 |
| P1-09 | import | 幂等 upsert + 内容版本号 + 变更 diff 输出 |
| P1-10 | 首批 Competency（10） | 见 §8 清单 |
| P1-11 | 首批 Pattern（7～10） | 见 §8 清单 |
| P1-12 | 首批 Template（10）+ 生成器 | 参数区间 + 约束，生成候选 item |
| P1-13 | 首批 Item（20～30） | 生成 + 人工复核（`review_status=approved`） |
| P1-14 | fluency_threshold 配置 | 按 `(competency, pattern, interaction_type)` 三维配置 |

### 验收

- `math-content validate` 与 `lint` 在 CI 中全绿
- 故意投毒测试：答案错误的 item、泄题的 hint、形成环的能力图、个位和 <10 的 make_ten 题目，**必须全部被拦下并给出明确错误码**
- `import` 重复执行两次，数据库状态一致（幂等）
- 20～30 个 item 全部 `review_status=approved`

### 风险

- **内容生产是整条路径上真正的瓶颈** → 对策：模板生成 + 认知校验 + 只做一条能力链；人工只做终审
- 模板生成退化为"数字随机变化" → 用 §6 的认知有效性规则作为 generator 的硬约束

## 5. 数据模型基线

### 5.1 学习域

```
competency(id, code, name, stage, description, active)
competency_prerequisite(competency_id, prerequisite_id, weight)
problem_pattern(id, code, name, competency_id, cognitive_type, difficulty, description)
misconception(id, code, name, description, severity, remediation_competency_id)
item(id, code, pattern_id, competency_id, difficulty, interaction_type,
     problem_json, answer_json, solution_steps_json, hint_chain_json,
     error_rules_json, estimated_seconds, template_id, source, review_status)
```

### 5.2 状态域（派生值不落权威）

```
-- 等级（🌱🌿🌳⭐🔥）不是字段，是 derive_level(signals, algorithm_version) 的结果（ADR-0002）
proficiency_state(child_id, competency_id,
                  mastery, accuracy, fluency, independence, transfer, confidence,
                  sample_count, assessment_samples, probe_status,
                  algorithm_version, updated_at)

-- 键必须带 competency：decompose 用在 make_ten 和用在 td_add_nocarry 上不是同一个技能，
-- 而"迁移"的定义恰恰是"同一能力、不同 pattern"
pattern_state(child_id, competency_id, pattern_id, 同上精简, method_distribution_json)

misconception_state(child_id, misconception_id, hit_count, last_seen_at, resolved,
                    remediation_competency)

review_schedule(child_id, target_type, target_id, stage_index, interval_days, due_at, ease)
```

### 5.3 事件域

```
learning_session(id, child_id, started_at, ended_at, duration_ms,
                 planned_minutes, item_count, story_count, completion, quit_reason, device)

attempt(id, session_id, child_id, item_id, competency_id, pattern_id,
        submitted_answer_json, correct, mismatch_flag,
        response_time_ms, active_time_ms, thinking_time_ms, idle_time_ms,
        hints_used, hint_level_max, method_used, assessment_flag, created_at)

learning_event(id, child_id, session_id, attempt_id, event_type, payload_json, ts)   -- append-only

coach_message(id, attempt_id, role, source(rule|llm), hint_level,
              text, validator_result_json, fallback_used, latency_ms, ts)
```

### 5.4 内容 / 故事域

```
universe(id, code, name, theme, unlock_rule_json)
story(id, universe_id, code, title, duration_min, target_competencies_json, order_index)

story_beat(id, story_id, sequence, beat_type(narration|challenge|reward),
           narration, visual_json, reward_json)

-- 一等实体：故事与题目之间的唯一桥梁
challenge_slot(id, story_beat_id, competency_id, pattern_id,
               difficulty_min, difficulty_max,
               selection_policy_json,   -- 候选过滤/排序/轮换规则（如"最近做过 make_ten 则换 decompose"）
               review_policy_json,      -- 复习与迁移要求
               estimated_time_s,
               scaffold_level,          -- blocks | decompose | direct
               purpose(teach|practice|review|challenge))
```

> **D1 的落地**：故事只声明"这里需要一个什么类型的挑战"，Planner 运行时选具体 item。
>
> ```
> Planner → ChallengeSlot → Candidate Items → Filter → Rank → Select Item
> ```
>
> 因此同一句"小熊需要把篮子装满"，强孩子拿到 `8+5`，弱孩子拿到 `7+3`，更弱的孩子拿到带积木脚手架的题——**故事固定，数学训练动态**。

### 5.5 内容版本 / 配置

```
content_release(id, version, imported_at, checksum, stats_json)
algorithm_config(id, version, payload_json, active, created_at)
```

### 5.6 游戏域

```
inventory(child_id, item_code, count)
unlock(child_id, unlock_code, unlocked_at)
reward_log(id, child_id, attempt_id, reward_json, ts)
```

### 8.2 Problem Pattern（9）

`direct_compute` / `decompose` / `number_friends` / `combine` / `increase` / `total` / `missing_part` / `reverse` / `represent_place_value` / `carry_exchange`

> 认知类型（cognitive_type）只允许：`compute / represent / strategy / apply / reverse`

### 8.3 Story → 能力映射（数字车站 10 个）

| # | 故事 | 目标能力 | 复习 | 重点 Pattern |
|---|---|---|---|---|

## 11. 各阶段 Definition of Done

### P2 DoD（最重要）

一个真实孩子能完整走完并留下正确数据：

```
进入数学世界 → 今日冒险 → 故事《火车来了》
→ 遇到 make_ten 挑战（slot 自动选到合适难度 item）
→ 答错 → 规则提示逐级升级 → 答对
→ POST /v1/attempts 落库（attempt + event + reward 同事务）
→ proficiency_state 变化可见（调试页）
→ 次日 GET /v1/plans/today 返回的计划因昨表现而改变
```

同时满足：
- 断网/提交失败时，本地缓存 attempt 并在恢复后重放（不丢数据）
- 刷新页面不产生重复 attempt（幂等键）

### P3 DoD

- 7 类模拟孩子（基础好快 / 基础一般理解快 / 会但慢 / 个位不熟 / 位值混乱 / 依赖提示 / 故事型）× 30 天 × 每天 10～15 分钟
- 报告必须回答：是否过早升级、是否长期卡简单题、回退是否频繁、复习是否过载、是否出现难度断层
- 至少 3 个真实孩子跑 2 周，人工确认系统判断与观察一致（**模拟数据不能替代这一步**）

### P4 DoD

- 泄题率 0（Answer Leak Detector 拦截率 100%，含"变相给出中间结果"）
- LLM 超时/异常/校验失败 → 100% 回退规则提示，孩子侧无感知中断
- 提示后继续尝试率、提示后正确率可观测
- 提示永远只包含"一个动作 + 一句鼓励"

## 12. 风险登记册

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 内容生产是最长路径瓶颈 | 拖垮全局 | 模板生成 + 认知有效性硬约束 + 只做一条能力链 |
| R2 | 故事绑死固定 item（D1 走错） | 自适应失效 | 一律用 `item_slot`，P1-07 强制校验 |
| R3 | 等级落库为权威（D2 走错） | 算法无法迭代 | 只存信号 + version，等级纯函数 |
| R4 | 时间采集不准（挂机/切页） | fluency 失真 | idle 分段 + 与 correctness/hint 联合判定 |
| R5 | LLM 泄题或超纲 | 破坏学习闭环 | 规则优先 + 4 个 Validator + 立即 fallback |
| R6 | 过早追求游戏性 | MVP 失焦 | 边界清单 + P5 才做成长体系 |
| R7 | 只用模拟数据自嗨 | 上线即失效 | P3 DoD 强制真实小样本验证 |
| R8 | 阈值硬编码 | 无法调参 | 全配置 + replay 重跑验证 |
