# ADR-0003：思考时间不是无效时间（时间语义冻结）

- 状态：已接受
- 日期：2026-09-15
- 取代：无

## 背景

计算流畅度（fluency）需要用到时间。最容易犯的错误是：

> 用"答题总耗时"当作计算速度，并且把"超过 5 秒没有操作"直接当作无效时间剔除。

对这款产品来说这是**方向性错误**：产品的目标就是培养思考。如果系统把思考误判成停顿并剔除，会从底层把学习方向带歪——孩子越是认真想，系统越认为他在划水。

## 决策

时间语义**冻结**为以下字段，且必须区别对待：

```
response_time_ms    # 题目出现 → 提交答案
active_time_ms      # 实际鼠标 / 触摸 / 键盘操作时间
thinking_time_ms    # response - active
idle_segments       # 分段记录，不是单一数值
```

分段判定阈值（初值，进配置）：

```
< 5s        正常思考
5s ～ 30s   可能是思考，也可能是停顿
> 30s       疑似离开 / 中断
```

**硬性规则：**

1. 禁止使用"超过 N 秒即视为无效"这类一刀切的剔除规则
2. `thinking_time` 与 `idle` 必须分开计算，`thinking` 是 **fluency 的合法输入**
3. 判定"孩子是否在思考"必须四项联合，禁止单看时间：

```
retry_delay + correctness + hint_usage + interaction_trace
```

4. fluency 阈值必须按 `(competency, pattern, interaction_type)` 三维配置，禁止一个标准套所有题型（direct 是秒级，story 是十几秒，lab 更长）

## 后果

**正面**

- 系统不会惩罚认真思考的孩子
- 可以观察"思考时间的变化"这一真实学习信号
- 为未来的"愿意思考"指标留下可信数据

**代价**

- 前端必须实现分段采集（`lib/telemetry`），不能用简单的 `Date.now()` 差值糊弄
- 需要区分"页面切走"与"孩子在想"，浏览器 `visibilitychange` 必须采集
- 数据量和实现复杂度上升，但这是产品的核心语义，不能省

## 违反时的表现（自检）

- 代码里出现 `if (elapsed > 5000) elapsed = 0` 之类逻辑 → 违反
- fluency 只用 `response_time` 而不区分 `thinking` → 违反
- 用同一个时间阈值衡量 direct 题和 lab 题 → 违反
