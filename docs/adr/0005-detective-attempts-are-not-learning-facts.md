# ADR-0005：侦探答题不是学习事实

- 状态：已接受
- 日期：2026-09-15
- 取代：无

## 背景

`POST /v1/detective/answer` 会在服务端判定对错并发放奖励，这让它看起来很像
`POST /v1/attempts`（ADR-0004 的唯一事实入口）。P2 收尾时留下的开放问题是：
侦探答题要不要写 attempt、要不要推进熟练度？

先看清侦探题考的是什么：线索推理（"它大于 20、小于 40、是偶数……"），
不是数学计算。孩子做对一道侦探题，证明的是**读线索、缩范围、做排除**的
推理过程；这里面没有任何一次加法、拆分或位值操作被真实执行。而熟练度的
5 个信号（mastery / accuracy / fluency / independence / transfer）度量的
全部是**数学计算能力** —— 它们的采样规则、fluency 阈值（按 pattern ×
interaction_type 配置）、升级门槛，没有一个是为"推理表现"设计的。

## 决策

**侦探答题不进入学习事实链路。** 具体边界：

1. `/v1/detective/answer` **不写 attempt、不写 learning_event、不更新**
   `proficiency_state / pattern_state / misconception_state / review_schedule`。
   它与数学实验室（契约 §7）同一语义：自由探索与游戏，不产生学习事件。
2. 判定照常做（服务端独立判定，与 ADR-0004 的双轨判定精神一致），结果
   只服务于当次交互（反馈、线索揭示），不沉淀为学习数据。
3. **reward 只走游戏侧**：侦探的奖励（材料 / 金币 / 解锁）与学习系统的
   reward_log 事务无关，不通过 attempt 关联，不推进成长体系里的学习型徽章。

一句话：**ADR-0004 说"学习状态只能从 attempt 进来"，本 ADR 补充它的反面
—— 不是所有答题都是 attempt。** 判定一个"答题"是否进入学习事实，看它
是否构成数学能力的证据，而不是看它有没有对错。

## 后果

**正面**

- 能力信号不被污染：孩子推理再强（或再弱），都不会让"凑十"的 mastery
  / fluency 长歪，家长报告与升级判定依然只反映数学计算
- 复习调度不受干扰：侦探答题不会制造或消耗复习档位
- 学习数据保持同质：replay、诊断、misconception 匹配都只面对真正的
  数学作答，不需要在每条路径上先排除侦探题

**代价**

- 侦探模块自己的表现数据目前不持久化（只回应当次），后续要做"侦探
  成就 / 排行"时需要另立存储，且必须与学习表分开
- 前端不能把侦探当成"练数学"的替代品误导家长 —— 家长报告里的活跃度
  数据不包含侦探，口径要在产品层讲清楚

## 将来若要接入学习链路，需要什么

接入是**被允许的，但必须满足以下全部条件**，且届时需新写 ADR 覆盖本条：

1. **新增专门的推理能力维度**（如 `reasoning` competency），与数学能力
   同一图谱但互不前置 —— 绝不能把侦探表现折算进现有数学能力的
   mastery / accuracy / fluency / independence / transfer。
2. **独立信号集**：推理能力的采样规则另配（例如"用了几条线索猜中"
   "错误缩放是否单调"），不复用为数学计算设计的 fluency 阈值与
   EWMA 参数。
3. **走 attempt 事实入口**：以带 `kind` 标记的 attempt（或独立事件表）
   进入唯一事实链路，保持 ADR-0004 的单事务与幂等语义，可 replay。
4. **配置先行**：新阈值全部进 `config/algorithm/`（ADR-0002），禁止
   字面量进代码。
5. **家长报告分开呈现**：推理维度在报告里独立成段，不与数学等级混排。

## 违反时的表现（自检）

- `/v1/detective/answer` 的处理路径里出现 `submit_attempt` /
  `persist_state` / 状态表写入 → 违反
- 家长报告或 debug 面板的数学信号在侦探答题后发生变化 → 违反
- 侦探奖励出现在 `reward_log` 且关联 attempt_id → 违反
- 复习调度因侦探答题而推进或回退 → 违反
